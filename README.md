# GuvianEye

**公网暴露面巡检工具** —— 纯 Python 标准库、零第三方依赖，在自己电脑上跑一个本地 Web 控制台，把「我负责的公网资产，这周比上周多开了哪些端口」讲清楚。

## 为什么做这个

做暴露面收敛的人都有同一个痛点：一堆公网 IP，每台到底开了哪些端口，谁也说不清。

市面上的扫描器不少，但大多解决的是「扫描」而不是「巡检」。巡检真正要回答的不是**「扫出来什么」**，而是：

> **这次比上次多了什么。**

新增的开放端口 = 暴露面扩大 = 要立刻处理。GuvianEye 就是围绕这一句话做的：报告自动和上一轮基线逐端口对比，新增的红色高亮，消失的也列出来，可以一键邮件推送。

还有一个更隐蔽的坑：**端口扫描会漏报，而且越用力扫漏得越多。**

高并发在几秒内对同一目标发出成千上万个 SYN，会触发目标侧/运营商侧针对你源 IP 的探测限速 —— 之后再怎么扫，连真实开放的 443 都不回你，且表现为超时而非拒绝。于是你得到一份「443 都没开」的报告，看起来像资产很干净，其实是自己被拉黑了。

GuvianEye 花了很大力气对付这件事（见下文「补扫」），并且**把判断过程透明地摊在报告里**，而不是装作自己永远不会错。

## 核心特性

**扫描引擎**

- **纯 Python 标准库**，`asyncio` 全异步 TCP connect，无任何第三方依赖，不需要 `pip install`
- **三态判定**：`open` / `closed`（收到 RST）/ `filtered`（无响应，被静默丢弃）—— 不把「没扫到」偷懒地写成「关闭」
- **自适应超时**：先用实测 RTT 探路，再把超时收紧到 5×RTT，兼顾速度与准确
- **主机发现**：ICMP + TCP 双探测，先剔除完全不可达的目标，不做无用功
- **重点端口补扫（机内）**：每台主机主扫描结束后，对仍无响应的重点端口降并发、拉长超时、多轮重探
- **全局后置补扫**：全部目标扫完后先冷却，再对业务端口做一轮低速兜底
- **开放端口二次确认**：多轮表决，任一轮收到 SYN-ACK 就保留，避免限速把真实开放端口误删
- **端口顺序打乱**：限速通常在累积若干 SYN 后生效，顺序扫会让某个端口之后的整片丢失；打乱后被丢的端口分散，更容易被补扫捞回
- **异常主机识别**：某主机开放端口数超阈值，判定为运营商安全设备统一应答 / 蜜罐，结果标记为**不可采信**，而不是傻乎乎报几百个高危
- **探测质量自查**：报告里明说本次有多少无响应、是否可能受本机网络限制

**巡检与对比**

- **基线 diff**：按「执行网络」分档存基线（`latest_<标签>.json`），新增 / 消失 / 变化逐端口列出
- **历史期望清单对照**：可选加载你自有的资产清单，回答「上次有、这次没扫到」到底是**真关闭**还是**漏扫**
- **定向复核**：对这批发疑端口做极低并发多轮重探，并同时探测该主机已知开放的端口作**对照**，能判定「本次探测无效」
- **跨批次取并集**：把历次复核结果合并，任一次测到过通即判为「历史已确证开放」

**交付与运维**

- **本地 Web 控制台**：四个页面（目标 / 扫描 / 结果 / 设置），点点鼠标即可，无需记命令
- **HTML 报告** + CSV + JSON，趋势图 / 摘要 / 处置建议 / 探测质量自查
- **邮件推送**（SMTP，自动重试，失败原因中文可读）
- **中断恢复**：主扫描一结束立即落盘 checkpoint，进程被杀也能几十秒重建报告
- **开机自启 + Windows 定时任务** 一键注册
- **地址段支持**：单个 IP / CIDR（`198.51.100.0/24`）/ 区间（`203.0.113.1-50`），带安全阀防止手滑写个 `/8`
- **命令行入口**：不想用控制台时可以直接 `python scanner.py`，方便接进已有运维平台

## 快速开始

**环境要求：Python 3.8+（推荐 3.10+），Windows / Linux / macOS 均可。**

```bash
git clone https://github.com/Guvian666/GuvianEye.git
cd GuvianEye
```

Windows 下双击 **`启动控制台.bat`**，浏览器会自动打开 <http://127.0.0.1:8899>。

手工启动：

```bash
cp config.example.json config.json     # Windows 下也可直接复制粘贴改名
python app.py                          # 控制台, 默认 127.0.0.1:8899
```

第一次使用三步：

1. **确认监听地址（安全）** —— 控制台默认只监听 `127.0.0.1`，仅本机可访问。
2. **填目标清单** —— 编辑 `targets.txt`，每行一个 IP / CIDR / 区间，`#` 开头为注释：

   ```text
   192.0.2.10                单个 IP
   198.51.100.0/29           CIDR 网段（自动展开）
   203.0.113.1-5             区间（尾段简写）
   ```

   > 上面是 RFC 5737 文档示例地址，请替换成你自己的资产。

3. **先预检，再扫描** —— 控制台「扫描」页先点【开始网络预检】（只测可达性，不碰业务端口），确认目标都到达得了，再点【开始扫描】。

想不打开界面直接跑：

```bash
python scanner.py --preflight        # 网络预检, 换网络后先跑这个
python scanner.py --mode common      # 快速扫描(约 600 个高价值端口)
python scanner.py                    # 全量 65535 端口
python scanner.py --mail             # 扫完发邮件
```

> ⚠️ **Windows 上那个黑色命令行窗口就是服务器本体。** 关掉浏览器页面没关系，关掉黑窗口 = 进程立即死亡 = 正在跑的扫描当场中断。窗口标题会随状态变化，一眼就能看出什么时候能关。

## 关于「补扫」，以及为什么 443 明明开放却扫不出来

这是本项目最核心的一段设计，值得单独说。

**根因**：探测速率 ≈ `concurrency ÷ 超时`。速率过高 → 触发目标侧对源 IP 的限速 → 之后该源 IP 的**所有**探测被静默丢弃（不回 RST，只超时）→ 表现为「明明开放却扫不出来」，而且**越用力扫漏得越多**。

**应对**（多层，默认开启）：

| 机制 | 时机 | 做什么 |
|---|---|---|
| 机内补扫 | 每台主机主扫描刚结束 | 对仍无响应的重点端口降并发 + 拉长超时 + 多轮重探 |
| 后置补扫 | 全部目标扫完后 | 先冷却等限速窗口过去，再对业务端口低速兜底 |
| 二次确认 | 每次判定开放之后 | 多轮表决，任一轮通即保留 |
| 顺序打乱 | 扫描全程 | 让被限速丢掉的端口分散而非整片缺失 |

**最有效的那个旋钮是 `concurrency`**（`config.json` 里）。调低会成比例拉长耗时，但显著减少漏报。默认 1000（≈500 SYN/s），如果报告里「疑似漏报」持续偏多，继续往下调（800 / 600）。

需要速度优先的测试跑法：控制台「扫描」页有个红色勾选项 **「跳过补扫（测试用：更快，但可能漏扫）」**，勾上只跑一遍主扫描。**它只影响本次运行，不会改动你的配置**，但报告顶部会打红字警告 —— 正式巡检请取消勾选。

## 已知限制

- 控制台**没有登录鉴权**。默认只监听 `127.0.0.1` 是刻意的；如果你想用 `--host 0.0.0.0` 暴露到局域网甚至公网，**请先自行加上反向代理与认证**。
- `filtered` 只能说明「没有回包」，**无法区分**目标端口被过滤、目标下线、还是你的执行网络被阻断。工具会在无响应占比过高时主动警告，而不是替你下结论。
- 依赖主机发现，对完全禁 ICMP 且不做 TCP 响应的网络段，结果会退化为「大面积无响应」。
- 报告与基线的对比**只对同一执行网络有意义**。换网络必须换标签重跑，否则会把网络差异误报成端口新增/消失。
